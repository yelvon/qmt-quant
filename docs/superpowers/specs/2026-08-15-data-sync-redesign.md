# ② 准备数据 — 交互重设计

> 日期：2026-08-15  
> 状态：已实现（方案 A）  
> 可视化稿：[data-sync-redesign.canvas.tsx](../../canvases/data-sync-redesign.canvas.tsx)

## 1. 问题

- 「历史长度」与「更新今日数据」语义冲突：用户选 5 年却点绿色按钮，只得 5 天。
- 两个 Primary 级按钮并列，无互斥关系。
- 同步计划（日期区间、耗时）不可见，完成后难以核对。

## 2. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 模式卡片互斥（推荐） | 顶部选「增量 / 全量」，参数与 CTA 随模式变化 | 心智清晰；实现量适中 | 需重构 DataPage 状态 |
| B. 分步向导 | Step1 选模式 → Step2 参数 → Step3 确认 | 首次用户友好 | 日常操作多一步 |
| C. 单按钮 + 高级折叠 | 仅保留「开始同步」，模式放高级 | 界面最简 | 模式仍易被忽略 |

**推荐方案 A**：互斥模式卡片 + 同步计划预览 + 单一主按钮。

## 3. 新页面结构

1. **状态条**：QMT · 股票池 · **本地已有日线范围**
2. **模式选择（互斥）**：增量更新 | 全量同步
3. **同步计划预览**（只读）：日期区间 · 股票数 · 预计耗时
4. **参数**：股票池 + 复权 +（**仅全量**）历史长度 1/3/5/10/20 年
5. **主按钮**：`开始增量同步` / `开始全量同步`（唯一 Primary）
6. **任务进度**：内嵌计划摘要；完成显示结果 +「查看已同步数据」
7. **数据健康**（保留）
8. **更多操作**（折叠）：财报 · 导出 · 修复

## 4. 互斥与默认

- `syncMode: incremental | full` 为单一状态源。
- `历史长度` 仅在 `full` 时渲染。
- 提交：incremental → `days: 5`；full → `range_preset` 必传。
- 运行中禁止切换模式（或 confirm）。
- 智能默认：无本地数据 → 全量 3 年；有新鲜数据 → 增量。

## 5. 额外优化

- 全量 10/20 年二次确认。
- 健康面板范围可点击跳转数据浏览。
- 完成后 Primary 改为「查看已同步数据」。
- `deriveSyncPlan()` 统一预览、CTA、进度文案。

## 6. QMT 历史数据上限

- **API 层面**：`download_history_data(2)` 无固定「最多 N 年」参数；`start_time` 留空时尽量从服务器可用最早数据开始。
- **实际深度**：取决于券商 MiniQMT 服务器与个股上市日；A 股常见为 **上市日起 ~ 20+ 年**，老股可能更长。
- **本项目**：「全部可用」预设从 **2005-01-01** 起请求（保守默认）；若需更早可后续支持自定义起始日或空 start 拉全量。

## 7. 验收

- [ ] 选全量 5 年 + 点开始 → 进度与预览均为 ~5 年区间
- [ ] 选增量 → 不显示历史长度；区间为近 5 交易日
- [ ] 两种模式不能同时「看起来像会执行」
- [ ] 页顶可见本地已有范围 vs 本次计划范围
